# Agnostic and ChatGPT target

Separate the desired target from actual host capabilities. Use existing project
conventions; for a new neutral project make `AGENTS.md` the authoritative entry,
with a thin `CLAUDE.md` pointer only when Claude portability is useful. Do not
presume every model reads either automatically.

## File-capable host

Read the authorized current entry/checkpoint and relevant files only. Write the
approved setup in the requested destination; record both language choices. Use
`agents/<role>.md` for needed procedural roles and `procedures/` for relevant
`new-wp`/`session-close` steps. A role card contains identity/reader, invariants,
mission, process/output and never-do boundaries; model tier is a preference only.
Read [roles](roles.md) when selecting/materializing them.

Use actual independent sessions only if available/authorized. A read-only mandate
is not a sandbox, and a role card does not register an autonomous process. If the
host cannot enforce permissions, state that. No configuration change, installation
or messaging another chat to emulate a missing capability.

With execution tools and an execution mandate, use the actual project checks;
with file access alone, mark commands prepared but not executed. Do not claim
native ChatGPT/Codex discovery or availability merely because a file exists.

## Conversation-only host or explicit no-write task

Work from supplied materials; do not claim access to unseen folders, a live repo,
independent agents or command execution. Produce named document drafts, role
instructions and runnable next checks in the chosen artifact language; speak to
the user in conversation language. Clearly mark them proposed/not saved and
checks not executed. A downloadable artifact is possible only if a real tool
creates it. Do not emit pretend success receipts.

Keep a concise checkpoint in the response if persistence tools are absent, and
explain how the user can save/provide it. Resolve only genuine missing decisions;
no filesystem or native-agent simulation presented as actual execution.

## Ordinary sessions after setup

Use entrypoint → HANDOFF/current WP → needed procedure. Do not reload the bootstrap,
all role cards or every source manual on each turn. Reuse complete unchanged context;
after compaction or changes recover only missing consequential instructions.

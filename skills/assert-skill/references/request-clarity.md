# Clarify consequential ambiguity

Use during kickoff when the supplied request leaves a consequential gap. Carry a
compact self-contained rule into the generated project so later requests and
scope changes do not require reloading Assert or repeating the full interview.
This is not a separate general-purpose prompt-rewriting mode.

## Reuse context, then identify the actual decision

Read only relevant supplied materials and current project decisions. Reuse known
answers, including both languages, audience, acceptance and explicit authority.
Clear requests proceed within their mandate; do not rewrite every prompt, ask
for ceremonial confirmation or add files to demonstrate that you checked.

Ask when a missing or conflicting choice would change the intended result or
reader, usable inputs, deliverable, action boundaries, cost or verification.
"Complete", "safe" or "cheap" are not automatic triggers if the agreed criteria
already resolve them. If they matter and remain unresolved, identify the choice
in plain language. Do not replace the user's intent with the agent's preference.

## Make clarification useful

- Group the necessary questions; for an ordinary task, one to three is a useful
  starting point, not a quota or hard cap. At kickoff retain the seven-category
  interview without asking already-answered questions again.
- Explain what changes with the answer. Offer a small set of meaningful options
  and one justified recommendation when possible. Label proposals and assumptions;
  do not invent facts, budgets, deadlines, sensitive-data decisions or permissions.
- Propose observable, proportionate acceptance if missing. An inspectable edit
  may suffice for prose; do not impose software tests or a full project setup.
  Technical/internal checks do not establish external adoption or usefulness.
- Clarify whether an ambiguous new idea replaces current work or belongs later.
  Respect explicit changes within their scope and explain consequential tradeoffs;
  do not freeze the old goal or quietly add another one. Continue authorized work
  that does not depend on the missing answer.
- Resolve essential gaps even after multiple rounds; no round limit permits
  guessing. Ask for approval only when a consequential choice or action remains
  unauthorized, not because every reformulation needs a new sign-off.

Capture durable decisions and observable success in the existing plan/checkpoint,
distinguishing user choices from agent proposals. Do not manufacture a new document
for each request. Materialize the compact rule in lean setup so the project can
apply it without this installed reference.

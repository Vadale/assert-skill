# What a completed setup contains

This is an illustrative content checklist, not a required empty directory tree.

- Goal, intended reader, measurable completion, non-goals and constraints.
- Declared size/stack/project-type/memory/comment choices and three priorities.
- Selected role/mission/tier/actual-model mapping, or honest single-session review.
- Three review levels with project-specific thresholds and sensitive surfaces.
- PLAN and a just-in-time ROADMAP: first WP prompt, files, exact acceptance, risks
  and fallback; later phase goals without speculative detailed tasks.
- ADR-000 stack, ADR-001 roles and ADR-002 visibility/license/product model.
- One authoritative project entrypoint, actual commands, checkpoint and useful diary.
- Only appropriate role/procedure/CI wiring; complete Core/T/P/D for code projects.
- Public/local material selection, required checks, observed results and limitations.
- WP0 ready when setup-only; continued work only if the mandate includes execution.

For a bounded S task, identifiable sections in one local working document may
carry plan, WP/acceptance, decisions, state and diary. Code controls remain a full
inspectable resource. Existing project conventions take precedence over new templates.

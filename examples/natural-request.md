# Start a project without inventing its answers

Illustrative dialogue and output outline, not a recorded setup or performance result.

## Natural request

> I want to start a local data-quality project. Talk with me in Italian and write
> project documents in English. Use the tools I already have; interview me before
> creating files and stop when the first work package is ready.

## Opening and setup

The assistant reuses the two language choices. It asks the remaining consequential
questions from the [interview](../skills/assert-skill/references/interview.md),
covering the problem and success criterion, constraints/private material, non-goals,
size, stack, distribution/license and priorities. Known answers are reused and
deducible choices are proposed openly; unrelated questions need not be repeated.

After the answers, it proposes an appropriately small structure and useful roles,
then creates the agreed project files in the authorized location. The result
identifies the first user's workflow, the next bounded work package and observable
acceptance, plus actual checks and unresolved limits. A small task can use one
compact working document. No team, subscription or implementation is automatic.

If a language choice is missing, it asks for that choice before substantive setup.
See the [opening conversation](first-conversation.md) and [setup outline](setup-result.md).

## Clarifying a later request

The generated project instructions keep a compact clarification rule. They reuse
known decisions without loading the kickoff skill again:

- “Complete the report” can proceed when the agreed indicators, chart and
  limitations already define completion.
- If the audience or meaning of “complete” changes the deliverable and is still
  unknown, ask a focused question, explain the tradeoff and propose a bounded
  option. Do not invent acceptance, a budget or permission.
- An explicit change of scope updates the current mandate; an ambiguous new idea
  needs a choice between replacing current work and saving it for later.

These are illustrative patterns, not a transcript or a guarantee for every model.
Clear requests need no prompt rewrite, repeated interview or routine reapproval.

## When to use another workflow

Resuming an established project from its handoff is continuity work. Implementing
an ordinary change or adding Python assertions does not require this kickoff.
